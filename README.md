# Mutation Testing and Fuzzing at Scale: Growing the WebGPU Conformance Test Suite

Experiment code for the ICST 2027 paper. We mutate Mesa's NIR compiler with
[Dredd](https://github.com/mc-imperial/dredd), find which WebGPU CTS tests reach each mutant
(run under Dawn and Lavapipe), check which reached mutants survive the CTS, fuzz with
WGSLsmith to kill survivors and unreached mutants, and reduce the killing programs to CTS tests.

The paper's research questions map onto the code as follows:

| RQ | What | Code |
|---|---|---|
| RQ1(a) | Per-test mutant reachability: isolated vs shared execution, shader cache | `icst_2027_experiments/reachability-stability/`, `analysis/` |
| RQ1(b) | Which reached mutants survive the CTS | `icst_2027_experiments/mutant-killing/kill*.sh` |
| RQ2 | Fuzzing survivors and unreached mutants with WGSLsmith | `icst_2027_experiments/mutant-killing/fuzz*.sh` |
| RQ3 | Reducing killing programs into CTS tests | `icst_2027_experiments/reduction/` |

Every number, table and figure in the paper is generated by
`icst_2027_experiments/figures_for_paper.sh` (see [Regenerating the paper's numbers](#regenerating-the-papers-numbers)).

---

## Requirements

- Linux with Docker. All tools (Mesa, Dawn, the CTS, Dredd, WGSLsmith, the reducers) are built
  inside Docker images; nothing else needs installing on the host.
- Python 3 with `numpy` and `matplotlib` on the host, for the analysis scripts
  (`pip install numpy matplotlib zstandard`).
- Disk: Docker writes to `/var` by default, so check it has room for the images and
  containers (or move Docker's data root).
- Memory: building and comparing the reach matrices (`matrix_compare`) needs about 40 GB.

Machines used for the paper: AWS `m7i.2xlarge` instances (8 vCPUs, 32 GB) for the reachability,
survival and fuzzing runs; a local server for the isolated cache experiment and the reductions.

## Repository layout

```

                             (run inside the image builds)

                             reduction and the WGSL passes (reduce, wgsl_pass, input_pass, export_tests)

  reachability-stability/    RQ1(a) reachability runs (isolated, shared, cache experiments)
  analysis/                  matrices, comparisons, runtimes, CTS test counts

  reduction/                 RQ3 selection, reduction and polishing

  figures_for_paper.sh       runs all the generators, in order
  generated/                 their output (\input by the paper)

```

## 1. Build the Docker images

```
bash docker/build_image_reachability_stability.sh    # dredd-webgpu-testing:reachability-stability
bash docker/build_image_mutant_kill.sh               # dredd-webgpu-testing:mutants, survival runs and fuzzing
bash docker/build_image_wgslsmith.sh                 # WGSLsmith (used by replay-reach.sh)
bash docker/build_image_reduce.sh                    # Perses, C-Vise and the WGSL passes
```

The reachability image contains the unmutated Mesa (`/data/mesa`), the tracking Mesa (`/data/mesa_tracked`) and the CTS used for
every run (`/data/cts`, commit given by `\CtsCommit` in the paper).

`docker/run_image_*.sh` start an interactive container for each image.

## 2. RQ1(a): reachability

### Isolated and shared runs

```
# isolated: one CTS test per process, one server; the manifest lists the tests to run
SERVERS=1 bash icst_2027_experiments/reachability-stability/run-isolated.sh <repeat-id> <individual_test_results.json>
# resume an interrupted isolated run
SERVERS=1 bash icst_2027_experiments/reachability-stability/run-isolated.sh <repeat-id> <individual_test_results.json> <run-dir>
# shared: the whole subtree and the file subtrees, four servers
bash icst_2027_experiments/reachability-stability/run-shared.sh <repeat-id>
```

- Both use the `dredd-webgpu-testing:reachability-stability` image and write a timestamped
  run folder under `results/webgpu-shader-run/`. Move each finished run with `mv` into the
  folders `figures_for_paper.sh` reads (set at the top of that script).
- The isolated runs used **one server** (`SERVERS=1`). `run-isolated.sh` defaults to
  `SERVERS=4`, so set it explicitly.
- The isolated manifest is the `individual_test_results.json` of the first execution, which
  lists every `webgpu:shader,*` test.
- Run times on one `m7i.2xlarge` (from the paper's runtime macros): an isolated repeat takes
  67–78 hours; a shared run 1.8–2.2 hours (whole subtree) or 5.8–7.3 hours (file subtrees).
- Five isolated repeats and five runs of each shared configuration. Shared runs go in
  `results/reachability/raw/` and are processed
  with `reachability-stability/run_process_shared.sh`.

### Reach matrices (long)

```
bash icst_2027_experiments/analysis/build_isolated_matrices.sh
bash icst_2027_experiments/analysis/build_shared_matrices.sh
```

One bit matrix (mutants x tests) per run, in `results/reachability/matrix/`. The isolated build
creates the shared row and column indexes (`mutants.txt`, `tests.txt`).

### Shader cache experiment

```
bash icst_2027_experiments/reachability-stability/cache_experiment.sh          # shared, cache off / cold / warm
bash icst_2027_experiments/reachability-stability/run-isolated-cache.sh        # isolated
```

Both write one folder per CTS subtree under the cache experiment's results folder. The isolated experiment resumes after
an interruption (subtrees with an `.isolated-done` marker are skipped).

### Runtimes

`analysis/check_isolated_runtime.sh --csv` and `analysis/isolated_runtime_from_archive.py`
write `results/reachability/runtimes/isolated_runtimes.csv`.

## 3. RQ1(b): survival

```
bash icst_2027_experiments/mutant-killing/kill-runner.sh <mutant_to_tests_isolated-no-cache.json> <run-name> <extra cts-lab kill args>
```

`kill-runner.sh` starts the `dredd-webgpu-testing:mutants` image (override with `IMAGE=`) and
runs `kill.sh` inside it (`cts-lab kill`, with the Mesa shader cache off and one Dawn runner).
The mapping is an isolated run's mutant-to-tests file (inside the repository, so the container
can see it). Output goes to `results/mutant-killing/<run-name>/`; the name has no timestamp, so
rerunning the same command resumes.

Each reached mutant is checked against the tests that reach it, stopping at the first test that
kills it. A test kills a mutant if it fails, crashes, or exceeds max(5 x unmutated time, 30 s).
Move each finished run with `mv` into `results/cts-survival/`, where `figures_for_paper.sh`
reads them (folders set at the top of that script).

## 4. RQ2: fuzzing

```
bash icst_2027_experiments/mutant-killing/fuzz-runner.sh <targets.txt> <outdir> --hours 72
```

`fuzz-runner.sh` starts the container and runs `fuzz.sh <targets.txt> <outdir> <extra cts-lab fuzz
args>` inside it: the WGSLsmith fuzzing kill loop against the mutant IDs in `targets.txt`.
Rerunning the same command resumes, skipping seeds already tried. Each trial ran on its own
machine.

The targets are the survivors from RQ1(b) (`survivors.txt`, from the `survival_combine` step) and the
unreached mutants (`icst_2027_experiments/generated/unreached_mutant_ids.txt`, from the
`unreached_ids` step of `figures_for_paper.sh`).

- Each trial runs for a fixed budget (`--hours`).
- Five 72-hour trials for each set, under `results/fuzz/` (folders set at the top of
  `figures_for_paper.sh`).
- Fuzzing timeout: max(5 x unmutated time, 10 s).
- The survivor trials did not record which targets each program reached; this is replayed with
  `mutant-killing/replay-reach.sh` (needs the
  WGSLsmith image).

## 5. RQ3: reduction

```
python3 icst_2027_experiments/reduction/select_reductions.py        # 38 mismatch kills -> selection.csv
bash icst_2027_experiments/reduction/run_selected_reductions.sh     # Perses, C-Vise, WGSL passes
FORCE=1 bash icst_2027_experiments/reduction/polish.sh             # final polishing (arguments: see the script's header)
```

- Selection: output-mismatch kills only; clustered (neighbouring mutants of the same source
  line) and dispersed (one per function), seed 1.
- Reductions run in the reduce image with the Mesa shader cache disabled
  (`MESA_SHADER_CACHE_DISABLE=true`, set in `reduce-runner.sh`).
- Each reduction takes a median of 4 minutes (2–26 minutes).
- Output: reduced and polished programs under `results/reduce/`.

## Regenerating the paper's numbers

Once the results are in `results/`, one script produces every macro, table and figure:

```
bash icst_2027_experiments/figures_for_paper.sh            # every step, in order
bash icst_2027_experiments/figures_for_paper.sh STEP ...   # only the named steps
bash icst_2027_experiments/figures_for_paper.sh --list     # list the steps
```

Two inputs are made separately, because they need Docker and the reachability image:

```
python3 icst_2027_experiments/gen_setup_generated.py \
    --out icst_2027_experiments/generated/setup_generated_macros.tex \
    --ranges-out icst_2027_experiments/generated/mutant_file_ranges.csv
python3 icst_2027_experiments/analysis/map_mutants_to_functions.py   # arguments: see the script's header
```

| Paper | Step | Output in `generated/` |
|---|---|---|
| Setup: CTS test counts | `cts_counts` | `setup_cts_counts.tex` |
| Setup: mutants, lines of code | (`gen_setup_generated.py`, above) | `setup_generated_macros.tex` |
| RQ1(a): reach, stability | `reach_summaries`, `reach_latex`, `merge`, `stability_latex` | `rq1a_reachability_macros.tex`, `rq1a_stability_macros.tex` |
| RQ1(a): shared vs isolated, Table 1, selection table | `shared_compare`, `matrix_compare`, `matrix_latex` | `rq1a_matrix_macros.tex`, `rq1a_reach_bands.tex`, `rq1a_selection_bands.tex` |
| RQ1(a): shader cache | `cache_latex` | `rq1a_cache_macros.tex`, `rq1a_isocache_macros.tex` |
| RQ1(a): runtimes | `runtimes` | `rq1a_runtime_macros.tex` |
| RQ1(b): survival | `survival_combine`, `survival_latex`, `cts_kill_rate` | `rq1b_survival_macros.tex`, `rq1b_killrate_macros.tex` |
| RQ1(b): where survivors and unreached mutants are | `survivor_analysis`, `const_folding_latex` | `rq1b_survivors_macros.tex`, `rq1b_*_files.tex`, `rq1b_const_folding_macros.tex` |
| RQ2: fuzzing | `unreached_ids`, `fuzz_compare`, `fuzz_compare_unreached`, `fuzz_latex`, `fuzz_latex_unreached`, `fuzz_combined_fig` | `rq2_fuzz_macros.tex`, `rq2_unreached_fuzz_macros.tex`, `rq2_kills_over_time_combined.pdf` |
